### 问题清单

#### 已修复严重问题

**Telegram offset 每批重写完整主状态**

- 位置：`internal/store/store.go`、`internal/store/store_postgres.go`
- 问题：每个非空 `getUpdates` 批次都经 `mutateAndSaveLocked` 刷新、快照、序列化并更新整份 `twilight_state`，造成 CPU、内存、数据库 I/O 与 Store 全局锁写放大。
- 修复：新增单行 `twilight_telegram_runtime` 表，以窄行 SQL 单调推进 offset；常规推进不再读取或改写主状态，Bot 身份变化时才允许清零。
- 证据：真库测试确认推进、防回退、重启恢复和清零均不改变 `twilight_state.version`。

**旧 JSON 快照游标可能无法迁移**

- 位置：`internal/store/store.go`、`internal/store/store_postgres.go`
- 问题：目标库先建运行时行再执行 `migrate-json` / `LoadSnapshot` 时，若只在启动阶段播种，会忽略快照中的旧 offset，存在重复执行历史 Bot 副作用的风险。
- 修复：启动和快照导入均以不回退方式迁移旧字段，随后从 JSONB 清除该字段；新备份不再携带过期运行游标。
- 证据：`TestOpenPostgresMigratesLegacyTelegramBotOffset`、`TestLoadSnapshotMigratesLegacyTelegramBotOffset` 真库通过。

#### 已完成性能与并发改进

- 更新批次按聊天、操作者和成员目标构建连通分量；共享任一身份的更新保持 Telegram 原始顺序，独立分量最多由 8 个 worker 并行执行。
- 批次函数等待所有 update 副作用完成后才返回，外层随后持久化 offset 并发起下一次长轮询，没有提前确认窗口。
- 单更新和单分组走无 worker 快路径；批次分组仅复制 map 引用，最大规模受 Telegram 单批更新上限约束。
- panic 继续按单 update 隔离，日志仅记录脱敏后的 panic 文本和数值 update ID。

#### 已修复测试基础设施问题

- API/Store 重置清单加入 `twilight_telegram_runtime`。
- 两个配置热重载用例显式保留 `[Admin]` 来源，测试不再错误依赖被自己删除的管理员配置。
- 运行日志测试对齐“每 256 条异步裁剪”的实现：允许裁剪前有限短暂超额，手动裁剪后仍要求精确上限。

### 问题清单

#### 已修复严重性能问题

**Telegram 花名册仍会重写完整主状态并永久占用堆内存**

- 位置：`internal/store/store.go`、`internal/store/telegram_roster.go`、`internal/store/store_postgres.go`
- 问题：新成员、状态变化以及每五分钟一次的普通群消息观察都经 `mutateAndSaveLocked` 刷新、快照、编码并重写整份 `twilight_state`；全部历史成员同时常驻 `State.TelegramRoster`，群规模增长会持续放大 CPU、数据库 I/O、Store 锁等待和 Go 堆。
- 修复：新增主键为 `(chat_id, telegram_id)` 的 `twilight_telegram_roster`。单成员观察使用窄行条件 UPSERT，定时成员检查使用一次 JSONB 批量 UPSERT；列表排序和统计聚合下推 PostgreSQL，运行状态不再保留全量花名册 map。
- 证据：真库断言单条与状态变化写均不改变 `twilight_state.version`，近期重复观察和重启后的冷缓存不会改变目标行 `xmin`。

**缓存故障可能压住后续持久化重试**

- 位置：`internal/store/telegram_roster.go`
- 问题：若先把观察写入节流缓存、数据库随后失败，后续同成员更新可能在五分钟内被误判为已经落库。
- 修复：缓存预留带单调 sequence；SQL 失败只在代际仍匹配时回滚原值或删除新预留，并发的新状态不会被旧失败覆盖。
- 证据：关闭数据库后的定向测试确认写入返回错误且缓存中不残留该 key。

#### 已完成迁移与资源边界

- 启动会把旧 `State.TelegramRoster` 幂等合并到专表，保留最早 `FirstSeen`、最新 `LastSeen/LastStatus` 和单调 `IsBot`，成功后从 JSONB 清除。
- `Snapshot` 把专表重新合并进兼容 `telegram_roster` 字段，`LoadSnapshot` 在事务中清表并恢复，空快照同样具有清空语义。
- 普通消息热缓存最多 4096 项；容量满时先清过期项，再按最早 sequence 淘汰。缓存 key 使用结构体，不再为每次查找拼接字符串。
- 管理端统计、踢出预览和调度任务会显式传播花名册查询错误，不再把数据库故障误判为“没有历史成员”后回退到不完整计划。
- API/Store 测试数据库重置清单已加入 `twilight_telegram_roster`。
