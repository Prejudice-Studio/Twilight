# 前端多语言开发与翻译指南

本文说明 Twilight 默认 WebUI（`webui-v2`）的文案组织、SSR 渲染和响应式文本约束。旧版 `webui` 的 JSON locale 体系只为紧急回滚维护，新功能不得继续写入旧版目录作为默认实现。

## V2 文案入口

V2 当前使用服务端可导入的 TypeScript 消息表：

```text
webui-v2/src/lib/i18n.ts
```

该文件导出 `t`，页面在 SSR 和浏览器增强阶段共享同一组稳定字符串。V2 页面应直接从 `$lib/i18n` 导入 `t`，不要在组件中新增硬编码的用户可见文案；涉及外部用户输入的内容仍必须作为文本节点输出。

```svelte
<script lang="ts">
  import { t } from "$lib/i18n";
</script>

<h1>{t.settings}</h1>
```

V2 的消息表目前以 `zhHans` 为默认语言实现。新增语言时，先为消息表建立同形的类型安全 catalog，再在 `+layout.server.ts` 根据受信任的用户偏好或部署策略选择语言；不得把语言选择放入跨用户的模块级可变状态。

## 新增文案

1. 为稳定业务语义命名 key，例如 `adminRequestsRefresh`，不要把显示文本作为 key。
2. 在 `webui-v2/src/lib/i18n.ts` 添加默认文案，并在使用页面导入 `t`。
3. 参数使用明确的替换 helper 或在页面中先格式化，用户输入只能作为参数值，不能参与动态属性名或 HTML 片段拼接。
4. 同步 `webui-v2/README.md` 或对应功能文档中的行为描述。
5. 运行 `cd webui-v2 && pnpm check && pnpm build`，检查 SSR 类型和生产构建。

旧 V1 若必须修复，只在 `webui/src/locales/` 中同步 `basic.json`、`zh-Hant.json` 和 `en-US.json`，并运行旧版自己的检查；这不会改变 V2 的默认文案来源。

## SSR 与安全

- `load` 和 form action 在服务端执行，不能把敏感配置、Token、密码或邮箱验证码放入消息表、URL 或浏览器持久化存储。
- 用户名、媒体标题、工单正文、管理员备注和外部 API 返回值必须通过 Svelte 文本插值渲染，不能拼接 `{@html}`。如确需富文本，必须先实现经过审查的白名单 renderer。
- 文案中的链接只能来自固定应用路径或经过后端/前端安全 URL 校验的值；不要把未校验的用户输入放进 `href`、`src`、CSS 或 form action。
- SSR 页面和会话数据使用 `Cache-Control: no-store`。语言 catalog 是构建产物的一部分，不应引入用户相关缓存键。

## 文本布局稳定性

Firefox 是桌面、手机、平板和窄 F12 视口基准。任何语言的文本都必须满足：

- 按钮和输入控件使用稳定的最小高度，允许标签换行，父元素设置 `min-width: 0` 和 `max-width: 100%`。
- 顶部导航、Tabs、工具栏在窄视口独立滚动或堆叠，不能用固定宽度把文字挤出页面。
- 表格保留列语义并在自己的滚动容器中横向滚动；长标题、用户名、注册码和工单编号使用安全断词。
- 对话框、下拉菜单和侧栏使用有界 `dvh` 高度、`overscroll-behavior` 以及 Firefox 标准滚动条。
- 不使用负字间距，也不通过 `vw` 任意缩放字号；标题级别应与容器密度匹配。

## 日期和数字

日期、数量和金额由组件使用 `Intl.DateTimeFormat` / `Intl.NumberFormat` 格式化后展示。不要把本地化日期写入后端状态，也不要用字符串替换模拟复数规则。API 的时间戳、UID 和计数仍按后端契约传输。

## 检查清单

- [ ] 默认实现修改的是 `webui-v2/src/lib/i18n.ts`，不是旧 V1 locale。
- [ ] 文案未包含真实 Token、密码、邮箱验证码或服务器地址。
- [ ] 用户输入仍作为转义文本渲染，没有新增 `{@html}`。
- [ ] 长文案在窄 Firefox 视口可换行或在所属容器滚动。
- [ ] 已运行 `pnpm check` 和 `pnpm build`。
- [ ] 若修改了旧版，仅作为回滚维护并注明，不改变生产入口。
